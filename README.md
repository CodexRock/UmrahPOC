# Autonomous Umrah planner — blocked capability proof

This is a runnable private development skeleton, not a completed live travel planner. The attached specification was assessed on 2026-10-26. The mandatory provider gate is **BLOCKED**: the installed CLI's remote plugin catalog returns HTTP 451 (`no_biscuit_no_service`). No supplier data, prices, XE conversion, or unattended Codex travel execution has been demonstrated.

Implemented: TypeScript/Fastify API, responsive single-page form, server-side password/session authentication, origin checks, bounded request size and rate, strict requests, SQLite WAL durable jobs, transactional claim, single active lease, queue limit, cancellation, interrupted attempt handling, 24-hour terminal retention, ownership checks, and an explicitly blocked worker. No paid resource was provisioned.

See [SETUP.md](SETUP.md), [CAPABILITIES.md](CAPABILITIES.md), [TEST_REPORT.md](TEST_REPORT.md) and [FEASIBILITY_REPORT.md](FEASIBILITY_REPORT.md).

The worker deliberately does not execute Codex until compatible tools, supported authentication, tool restrictions and genuine event evidence are established. Its blocked result cannot be used as an adapter for live providers. There is no fixture inventory in the UI.
